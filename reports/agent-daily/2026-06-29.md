### 1. Wayfinder Router：确定性模型路由进入 Agent Harness 视野

- **来源**：Hacker News 热门（buzzing.cc 中文翻译）
- **时间**：2026-06-28T16:58:56.073Z
- **链接**：https://github.com/itsthelore/wayfinder-router
- **分类标签**：`LLM Gateway`、`model routing`、`cost governance`、`agent harness`、`deterministic routing`
- **一句话摘要**：Wayfinder Router 通过 prompt 结构和规则在本地与托管 LLM 之间做微秒级确定性路由，不调用额外模型。
- **文章做了什么**：提供一个可自托管的模型路由器，基于提示词长度、标题、列表、代码、数学、硬约束等结构特征决定请求应该走本地模型还是托管模型。
- **核心技术/架构**：确定性规则路由、OpenAI 兼容 API、Ollama / Anthropic / Groq / vLLM 支持、离线路由、低延迟、可校准阈值、dry-run 演示。
- **为什么重要**：企业 Agent 不可能所有任务都使用最贵模型；模型选择需要可解释、低延迟、低成本、可审计。
- **对我学习 AI Agent 工业级开发的启发**：`msinsight_agent` 未来可在 Harness 层记录 `task_type / selected_model / routing_reason / estimated_cost / latency / quality_result`，把模型选择纳入可观测和可评测范围。
- **后续追踪问题**：确定性路由是否适合作为 `msinsight_agent` 的默认模型选择策略？是否需要在 trace 中记录 `routing_reason`？

- **一句话摘要**：研究者用 76 个 MCP 工具让 Claude、GPT、Gemini 等模型玩《文明 VI》，发现模型主动检查全局状态仅占 1-2%，计划后 10 回合执行率只有 48-66%。
- **文章做了什么**：把复杂游戏环境通过 MCP 工具暴露给模型，并观察模型在多回合策略、状态感知和计划执行上的表现。

- **为什么重要**：Agent 的失败常常不是工具不够，而是没有主动读取状态、没有执行计划、没有形成闭环。

- **一句话摘要**：Adrafinil 是 macOS 菜单栏工具，仅在 Claude Code、Codex、Cursor、Gemini CLI、Aider、Cline 等 AI coding agent 有活跃会话时阻止系统睡眠。
- **文章做了什么**：通过各 Agent 的 hook 系统调用 CLI，判断是否存在活跃会话，并用引用计数断言、温度阈值释放、空闲释放等机制控制系统睡眠。

- **为什么重要**：Coding Agent 正在从短对话工具变成长时间运行的本地任务，需要 OS 层、hook 层和进程层运行时支持。

## 新概念 / 新框架 / 新协议 / 新评测

- **Wayfinder Router**：确定性模型路由器；重要性在于把模型选择变成低延迟、低成本、可解释、可审计的 Harness 能力。
- **Deterministic Query Routing**：不调用另一个 LLM 做路由，而是用规则和结构特征决策；重要性在于降低随机性和不可解释性。
- **CEO-Bench**：长期经营型 Agent benchmark；重要性在于评测长期策略、资源管理和连续决策，而不是单轮问答。
- **Long-running Agent Strategy Eval**：长期任务评测方法；重要性在于工业级 Agent 经常需要跨多轮、跨时间保持目标一致。
- **MCP-based Game Environment**：用 MCP 工具暴露复杂游戏环境；重要性在于 MCP 可作为 benchmark 环境接口，而不只是业务工具协议。
- **Perception-Action Gap**：Agent 知道很多但不主动感知状态或不稳定执行；重要性在于解释“工具多但任务仍失败”的常见问题。
- **Active State Checking Rate**：Agent 主动检查全局状态的比例；重要性在于可迁移为 `DiagnosisContext read rate`。
- **Plan Execution Rate**：Agent 制定计划后实际执行的比例；重要性在于可迁移为 `plan_step completion rate`。
- **AI Coding Agent Hooks**：通过 Agent hooks 感知任务是否活跃；重要性在于 Hooks 正成为本地 Agent Runtime 和宿主系统协作的基础设施。
- **Parameter Compression-Coverage Hypothesis**：推理模式可压缩，事实知识难压缩；重要性在于说明小模型仍需要 RAG / Knowledge Base 补充事实。
