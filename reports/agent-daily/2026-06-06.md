### 1. GitHub 开源 Spec Kit 工具包，用产品规范引导 AI 编码

- 来源：X / Rohan Paul
- 时间：2026-06-06T13:07:16Z
- 链接：https://x.com/rohanpaul_ai/status/2063246343842501091
- 分类标签：agentic coding、spec-driven development、workflow、coding agent governance
- 一句话摘要：Spec Kit 通过先写产品规范、再澄清差距、制定技术计划和拆解任务，约束 AI 编码 Agent 的执行过程。
- 文章做了什么：提出一种反向编码流程，不让 AI 直接从松散提示开始写代码，而是先形成产品功能规范，再把规范变成开发合约，最后交给 Agent 执行。
- 核心技术/架构：spec -> clarification -> technical plan -> task decomposition -> agent execution；支持 Copilot、Claude Code、Codex、Gemini、Cursor、Qwen 等 30+ Agent 集成。
- 为什么重要：coding agent 最大风险之一是需求不清导致返工、边界遗漏和错误实现，Spec Kit 把“需求规范”前置为 Agent 可执行约束。
- 对我学习 AI Agent 工业级开发的启发：Agentic coding 的关键不是让 Agent 更自由，而是给它更明确的规格、任务边界和验收标准。
- 后续追踪问题：Spec Kit 的规范格式是否可作为 coding agent eval/harness 的输入？能否接入本地项目形成“spec -> PR”的工作流？

## 新概念 / 新框架 / 新协议 / 新评测

- Spec-driven agentic coding：先产出产品规范和技术计划，再让 Agent 执行，降低 vibe coding 的需求不清风险。
- Agent Arena：基于真实任务、工具调用和用户反馈的 Agent 评测体系，比静态 benchmark 更接近生产环境。
- Agentic RAG：用规划、路由、迭代检索和上下文评估增强 RAG，适合复杂企业多源数据查询。
- Cross-Corpus Retrieval：跨多个企业语料库进行检索，是企业级 RAG 的关键能力。
- Small-model multi-agent simulation：用小模型构建多智能体仿真时，环境规则和提示约束比单纯模型规模更关键。
- Coding agent regression risk：AI 参与代码维护可能引入质量风险，需要测试、审查和可观测机制兜底。
