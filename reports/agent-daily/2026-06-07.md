   - 为什么重要：它把 Agentic Coding 的上游上下文从隐式对话变成可审查、可复用、可交接的工程文档。

3. MiniMax M3 与 Claude Opus 代码审计对比提醒：coding agent 评测要工程化
   - 重点：同一代码库、同一提示词、预植入 17 个 bug，比较检出数量和成本。
   - 为什么重要：Agent 评测不能只看模型名或主观体验，要看任务定义、oracle、检出率、误报率、成本和复现性。
   - 学习启发：后续可设计一个小型植入 bug benchmark，用于测试 coding agent 的代码审计能力。

## 今日重点讨论补充

### Spec Kit + Superpowers 协同范式

- 你的理解：Spec Kit 工具包可以替代 Superpowers 中 brainstorming 的部分，将宏观架构设计从隐式变成显式文档化。
- 补充后的分工：Spec Kit 负责 `spec.md / plan.md / tasks.md`，主导模块、技术栈、数据模型和验收标准；Superpowers 负责函数级设计、编码实施、测试验证和经验沉淀。
- 工程意义：这相当于把 Agentic Coding 拆成“规格层”和“执行层”，减少 Agent 在编码阶段重新发明需求和架构的概率。

## 新概念/新框架/新协议/新评测

- Spec-driven agentic coding：用规格、计划和任务文档约束 coding agent 执行，减少上下文漂移。
- Spec Kit：面向 AI 编码的规格驱动工具包，适合承担 Agentic Coding 上游设计层。
- Spec Kit + Superpowers 协同：Spec Kit 做宏观规格与 plan，Superpowers 做函数级实施与验证。
- 多模型 Agent runtime：多个异构模型协作时需要统一服务适配、状态管理和失败处理。
- 容忍性 JSON 解析层：提升多模型结构化输出的鲁棒性。
- 记忆情绪摘要截断：用摘要压缩历史上下文，避免长期运行 Agent 被记忆淹没。
- 信息隔离 / 真相防火墙：防止多 Agent 系统中不该共享的信息进入 prompt 或行为链路。
- 植入 bug 的 coding-agent benchmark：用已知缺陷评估 Agent 的代码审计检出能力、成本和误报。
- 工具调用式研究 Agent：搜索、证据收集、事实清单、假设生成和追溯检查组合成研究工作流。

## 今日学习建议

- 最值得深挖：`Spec Kit + Superpowers` 协同工作流。
- 建议阅读重点：Spec Kit 的文档结构、命令流程、任务拆解方式，以及它如何与现有 coding agent 协作。
- 30-60 分钟实践：为日报生成流程写一个最小 `spec.md / plan.md / tasks.md`：
  - `spec.md`：定义报告目标、数据源规则、输出结构和验收标准。
  - `plan.md`：定义数据读取、Agent 打标、Markdown 渲染、UTF-8 校验、Git 提交模块。
  - `tasks.md`：拆成读取快照、分类过滤、生成报告、验证编码、提交上传五个任务。
