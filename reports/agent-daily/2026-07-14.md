### 2. Tokenizer 差异导致真实代码成本变化：Agentic Coding 必须做成本评测

- 来源：Hacker News 热门 / PlayCode
- 时间：2026-07-13T21:50:30.963Z
- 链接：https://playcode.io/blog/real-price-of-frontier-models
- 分类标签：`agentic coding`、`cost governance`、`tokenization`、`model routing`、`harness/eval`
- 一句话摘要：同一份 TypeScript 文件在 GPT-5.x 上为 681 tokens，在 Claude 最新 tokenizer 下为 1178 tokens，相差 1.73 倍；Anthropic 新 tokenizer 在代码上比旧版多产生约 30% token。

为什么重要：

- Agentic Coding 场景里，输入通常是代码 diff、文件片段、日志、测试输出，tokenizer 对真实成本影响很大。
- 标价相同不代表实际成本相同；不同 tokenizer 会改变路由策略。
- 这应进入 `Provider Abstraction / Cost Governance / Harness`。

建议映射到 eval checklist：

```text
same_code_sample
-> token_count_by_model
-> prompt_cost_by_model
-> completion_cost_by_model
-> quality_score
-> latency
-> routing_decision
```

## 新概念/新框架/新协议/新评测

- **Agent Control Plane**：用户、系统或上层编排器用来规划、重定向、排队、审查、暂停、恢复和限制 Agent 执行的控制接口集合；重要性在于让 Agent Loop 可控、可审计、可恢复。
- **Steer**：运行中重定向当前 Agent 任务；重要性在于支持用户中途纠偏，而不是只能取消重来。
- **Queue**：给当前 Agent 运行排队下一条消息；重要性在于支持不中断当前步骤的后续指令管理。
- **`/plan` `/goal` `/review`**：Codex 的显式控制命令；重要性在于把规划、目标设定和产物审查从隐式 prompt 变成可记录的控制事件。
- **Tokenizer Cost Benchmark**：用同一代码样本对不同模型 tokenizer 计数并估算真实成本；重要性在于 Agentic Coding 成本治理必须基于真实输入，而不是只看公开单价。
- **Agentic Data Flow**：Agent 化数据处理流程；重要性在于 RAG 上游 OCR、清洗、校验、补全、chunking 可以作为 workflow 编排。
- **OmniDocBench**：文档 OCR / 解析能力评测；重要性在于 RAG ingestion 质量需要独立评测。
- **Artifact-level HITL**：用户直接在图像、文档、代码 diff 或产物上标注修改意图；重要性在于 HITL 从确认/拒绝扩展到细粒度产物审查。
