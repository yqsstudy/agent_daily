```text

-> approval gate
-> external side effect
-> audit log

```

### 3. Agent Memory Dosage：智能体记忆并非越多越好

- 标题：智能体记忆并非越多越好：八款模型评测显示剂量需按能力校准
- 来源：Hugging Face / IBM Research
- 时间：2026-08-18T18:09:38Z
- 链接：https://huggingface.co/blog/ibm-research/altk-evolve-hmm
- 分类标签：`agent memory`、`context engineering`、`trajectory distillation`、`memory selection policy`、`token budget`、`model capability tier`
- 一句话摘要：研究显示 Agent 记忆注入需要按模型能力调剂量，强模型适合完整指南集，较弱模型采用精选检索效果更好。

文章做了什么：

- 评测 8 款模型在不同记忆注入策略下的任务表现。
- 从 Agent 过往轨迹中蒸馏指南，并在推理时注入。
- 发现不同能力模型适合不同记忆剂量。

核心技术/架构：

```text
past_agent_trajectories
-> distilled_guidelines
-> memory_selection_policy
-> model_capability_tier
-> retrieval_or_full_injection
-> task_success_delta
-> token_cost
```

为什么重要：

- Agent 记忆不是越多越好；过量记忆会增加 token 成本、噪声、过期上下文和错误迁移风险。
- 记忆策略需要按模型能力、任务类型和预算调参。
- 这与 `SessionStore / long-term memory / context slimming` 强相关。

对我学习 AI Agent 工业级开发的启发：

- `SessionStore` 应支持 `memory_source / freshness / selected_reason / token_budget / model_capability_tier`。
- `Memory Dreaming` 不应只是压缩历史，而应生成可控、可检索、可验证的 lightweight memory。

后续追踪问题：

- Agent memory dosage 的模型能力分层如何定义？
- 如何避免从失败轨迹中蒸馏出错误指南？
- 记忆注入策略如何映射到本地 `SessionStore`？

## 新概念/新框架/新协议/新评测

- **Office Action Agent**：可直接操作邮件、网盘、文档的 Agent；重要性在于真实外部副作用需要审批、审计和回滚。
- **Claude Gmail / Drive Connector**：办公工具连接器；重要性在于 Agent 从问答进入真实 SaaS 动作执行。
- **On-call Agent**：面向事故响应的一线值班智能体；重要性在于把告警、日志、指标、代码和人类协作串成闭环。
- **On-call Agent Evidence Chain**：事故 Agent 的证据链；重要性在于区分模型猜测和证据支持结论。
- **GitHub Skills File for Incident Response**：用 skill 文件组织事故响应 playbook；重要性在于把运维经验转成 Agent 可执行流程。
- **Memory Dosage**：按模型能力控制记忆注入量；重要性在于过量记忆会带来噪声、成本和错误。
- **Cyber Capability Release Gate**：模型达到关键网络能力阈值时放缓或阻断发布；重要性在于能力释放需要安全门控。
- **Multi-stage Activation Classifier**：多阶段激活分类器；重要性在于检测高风险网络能力触发。
- **Eval Clarity First**：评测先明确任务、指标、样本和判分标准；重要性在于避免漂亮图表掩盖无效评测。
- **Inspect AI + Harbor**：Agent 技能评测工具组合；重要性在于可用于构建可复现评测链路。
- **Scientific Agent Workflow**：科学任务中的候选生成、实验验证和反馈循环；重要性在于 evidence-backed workflow 不只适用于软件工程。
