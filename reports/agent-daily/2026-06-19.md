### 1. Elasticsearch 发布持久化 Agent Memory 层

- **来源**：Elastic Search Labs / Hacker News 热门
- **时间**：2026-06-19T05:01:18Z
- **链接**：https://www.elastic.co/search-labs/blog/agent-memory-elasticsearch
- **分类标签**：`agent memory`、`MCP`、`persistent memory`、`hybrid retrieval`、`multi-tenant isolation`、`memory eval`
- **一句话摘要**：Elastic 基于 Elasticsearch 构建持久化 Agent Memory 层，将记忆分为情景、语义、程序三类，支持 MCP 客户端访问，R@10 达 0.89，且零跨租户泄漏。
- **文章做了什么**：给出一个可工程落地的 Agent Memory 层：不同记忆类型分别建索引，使用 BM25、Jina v5 稠密向量、RRF 融合和交叉编码器重排，并用 QA 任务评估召回。
- **核心技术/架构**：episodic memory、semantic memory、procedural memory、独立索引、混合检索、rerank、MCP 接入、跨租户隔离。
- **为什么重要**：Agent Memory 从“聊天历史总结”升级为可检索、可过期、可隔离、可评测、可协议化访问的持久层。
- **对我学习 AI Agent 工业级开发的启发**：需要重新区分 `SessionStore / RAG 知识库 / Evidence / Learning Record` 的职责，不能把所有长期信息都混称为 memory。
- **后续追踪问题**：`msinsight_agent` 中哪些信息属于 runtime state，哪些属于 memory，哪些属于 audit evidence？

- **对我学习 AI Agent 工业级开发的启发**：你的系统在学习阶段可先直连模型，但工业化阶段应补一层模型访问抽象。

## 新概念 / 新框架 / 新协议 / 新评测

- **Persistent Agent Memory Layer**：把 Agent 记忆做成持久化服务层，支持长期任务、跨会话恢复和可评测召回。
- **Episodic / Semantic / Procedural Memory**：情景、语义、程序三类记忆分开建模，便于不同生命周期、召回策略和写入频率。
- **MCP-accessible Memory**：通过 MCP 暴露 Memory 服务，使 Memory 成为可插拔 Agent 能力，而不是框架内部黑盒。
- **Temporary Accounts for Agents**：给 Agent 使用的短生命周期云账号，降低部署摩擦并减少长期凭证风险。
- **LLM Gateway / AI Control Plane**：统一管理模型访问、路由、故障转移、护栏、日志、成本和合规。
- **Code as Action Interface**：Agent 通过写代码组合工具和中间结果，比固定 tool schema 更灵活，适合复杂推理任务。
- **Agentic Research Loop**：Agent 自主完成实验设计、代码、调度、debug、总结，把研究过程变成可执行 workflow。
- **Memory Evaluation**：用 R@10、跨租户泄漏、重排效果等指标评估 memory，避免“感觉有记忆”的伪工程。
- **Skill Engineering Loop**：`自己用 -> 发现问题 -> Agent 分析 -> 出方案 -> 测试覆盖 -> 更新 Skill`，把 Skill 当成可持续迭代资产。
- **Artifact-producing Skills**：Skill 输出 PPT、网页、笔记、视频等 artifact，让 Agent 输出成为可协作、可复用成果。
