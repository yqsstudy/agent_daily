### `DiagnosisAgent.resume()` 与可恢复执行现场

今天学习重点是 Agent 层 Resume 机制，并生成学习卡片：

- `D:\Project\agent-learning\learning-records\0011-understand-agent-pending-input-resume.md`

核心理解：

```text
Resume 不是“继续聊天”，而是“恢复一个被序列化保存过的执行现场”。
```

关键点：

- `resume_action` 决定恢复分支：如 `select_playbook`、`continue_mcp_with_args`。
- `suspended_metadata` 是轻量 checkpoint，保存 `diagnosis_id`、`pending_id`、`tool_name`、`tool_schema`、`required`、`resolved_arguments`、`original_message` 等。
- `pending_id` 不决定恢复分支，它用于定位和清理旧 pending。
- `RESTART_DIAGNOSIS` 不是恢复原任务，真正恢复主路径是 `ANSWER_PENDING -> agent.resume(...)`。

## 新概念/新框架/新协议/新评测

- `Tool Calling Is Not Enough`：工具调用只是能力入口，Agent 还需要状态、权限、上下文、恢复、观测和人机协同。
- `Agent Runtime Full Rebuild`：旧助手架构无法满足新 AI Agent 产品目标时，需要重构 Runtime，而不是继续打补丁。

- `Platform RAG / Public Data Grounding`：从平台公开数据中检索并合成答案，关键是来源边界、引用可信度和纠错机制。
- `Enterprise Customer-Service Agent Platform`：企业客服 Agent 走向平台化，关键能力包括知识库、权限、handoff 和审计。
