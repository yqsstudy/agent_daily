## 今日摘要

今天的主线是 Agent 工业化从“让 LLM 自由 ReAct”走向“Runtime/Harness 受控执行、Evidence 证据约束、Benchmark 可评测”。热点中最重要的是 Harness-1、OpenAI Harness Engineering、Her Claude Code 会话分析、ChatGPT Super App，以及 NVIDIA + Doosan 的 Agentic Robot OS。当天对话进一步把这些内容迁移到 Insight 2.0 架构：通用 Agent 可以做 Brain，但 Insight 应自研 Diagnosis Harness / Domain Agent Controller，掌握流程、证据、权限、验证和 UI action。

## 最重要3件事

1. Harness-1 将 Agentic RAG 的多轮检索做成可训练、可评测的检索子系统
   - 重点：20B 检索子智能体负责搜索决策，Stateful Search Harness 维护搜索历史、候选证据池、压缩摘要、去重、证据图、验证记录和停止条件。
   - 为什么重要：它说明复杂检索不能只靠一次 TopK，需要工程系统管理状态和证据。

2. Harness Engineering 成为 Agentic Coding / 工业级 Agent 的关键方法
   - 重点：不能只依赖 ReAct + skill 软约束，需要可控执行环境、工具边界、证据绑定、verifier 和 eval。
   - 为什么重要：它直接对应你本周 Harness/Eval/Benchmark 学习主线。

3. Insight 2.0 的方向应从“接通用 Agent”升级为“自研 Harness-first 领域 Agent Controller”
   - 重点：通用 Agent 可负责语言理解、推理解释、报告生成；Insight 必须自研 Eyes、Hands、Evidence、Policy、Workflow、Verifier 和 Trace。
   - 为什么重要：这是把通用 Agent 真正落到高可靠性能调优产品的关键边界。

## 今日重点讨论补充

### Harness-1 的个人理解修正

- 你的理解: Harness-1 训练了一个专门用于检索的 20B 模型，配合状态管理 Harness 实现高质量检索。
- 修正后: Harness-1 是 Agentic RAG 中“多轮检索与证据整理”的关键子系统，不是完整 Agentic RAG 产品。
- 关键工程启发: 复杂检索状态不应全部交给 LLM，而应由 Harness 管理搜索历史、候选证据池、证据图、验证记录和停止条件。

### Runtime、Harness、Benchmark、Evidence 的边界

- Runtime: 让 Agent 跑起来的执行底座。
- Harness: 让 Agent 在受控条件下运行、记录、验证、评分和回放。
- Benchmark: 任务集、标准答案和评分规则。
- Evidence: 支撑 Agent 结论的可验证依据，不等于 citation，也不等于工具调用链路。

### Function Calling 中的 Evidence

- 方法调用链路是过程证据的一部分。
- 完整 evidence 还包括工具返回结果，以及最终 claim 与 tool result 之间的绑定关系。
- 关键句: Trace 说明 Agent 做了什么；Observation 说明工具返回了什么；Evidence 说明最终结论凭什么成立。

### Insight 2.0 Agent Bridge 评审

- 核心判断: Insight 不应只接通用 Agent，而应自研 Harness-first 的领域 Agent Controller。
- 推荐架构: 通用 Agent 做 Brain；Insight 自研 Diagnosis Harness 做 Controller；Insight 现有分析能力做 Eyes 和 Hands。
- 必补模块: Evidence Object Model、Trace/Observability、Eval Harness、Context Budget Strategy、Agent Capability Negotiation、Permission Gate、Verifier。

## 新概念/新框架/新协议/新评测

- Harness-1: 面向复杂检索的 20B retrieval subagent，用 Harness 管理搜索状态并评估 curated recall。
- Stateful Search Harness: 有状态搜索脚手架，维护候选证据池、证据图、验证记录和停止条件。
- Curated Recall: 衡量经过筛选和验证后的高质量证据召回，而不是普通召回数量。
- Harness Engineering: 为 Agent 设计可控执行环境、工具边界、反馈和验证机制。
- Agent Runtime: Agent 的执行底座，负责循环、状态、工具、权限、记忆和日志。
- Agent Harness: 评测、训练、调试和治理 Agent 的受控夹具。
- Evidence Object: 将 Agent 结论绑定到可验证依据的数据对象。
- Function Calling Evidence Chain: tool call trace + tool observation + claim-evidence link。
- Bug Oracle: coding agent benchmark 的标准答案，用于计算 TP/FP/FN、precision、recall。
- Diagnosis Harness: 面向 Insight 性能调优的受控 workflow/verifier/evidence/controller 层。
- Agent Capability Negotiation: 根据外部 Agent 能力决定上下文注入、工具开放和结构化输出要求。
