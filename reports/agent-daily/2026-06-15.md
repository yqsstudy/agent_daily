### Agent 层：`PendingInput` 与 `resume_action` 是可恢复执行现场

今天继续走读 Agent 层挂起恢复链路，形成了以下理解：

```text
DiagnosisAgent.run()
  -> AgentResult(status="suspended", requirement=...)
  -> Orchestrator 创建 PendingInput
  -> user_input_required SSE
  -> 用户再次输入
  -> PendingInputRouter.route()
  -> DiagnosisAgent.resume(..., pending.metadata)
  -> 根据 resume_action 恢复执行
```

关键判断：

- `DiagnosisAgent` 不直接面向前端；它返回 `AgentRequirement`。
- `Orchestrator` 负责持久化 `PendingInput` 并转换成 SSE。
- `PendingInputRouter` 解决 pending 状态下用户输入歧义：回答问题、暂停、取消、重启、查状态、切换话题。
- `RESTART_DIAGNOSIS` 不是恢复原任务；真正恢复主路径是 `ANSWER_PENDING -> agent.resume(...)`。
- `suspended_metadata` 是轻量 workflow checkpoint，保存 `resume_action`、`diagnosis_id`、`pending_id`、`tool_name`、`tool_schema`、`required`、`resolved_arguments` 等执行现场。

## 新概念 / 新框架 / 新协议 / 新评测

- `Architect-Builder Pattern`：强模型做规划/审核，便宜模型做执行；重要在于降低长程 Agent 成本。
- `Cost-aware Routing`：根据任务阶段、风险和证据状态动态选择模型；重要在于让 Agent Runtime 可规模化运行。
- `Containerized Agentic Eval`：在容器中评测 Agent 多步执行；重要在于隔离副作用并复现环境。
- `Skill 化工作流`：把经验、prompt、约束和验证方式封装成可安装资产；重要在于沉淀可复用 Agent 能力。
- `PendingInput`：Agent 挂起时面向前端和 Orchestrator 的输入契约；重要在于让 HITL 可结构化。
- `suspended_metadata / resume_action`：保存挂起现场并决定恢复路径；重要在于实现真正的 Suspend -> Ask Human -> Resume。
- `MCPControlFlow`：把 MCP 工具异常转成 `NEEDS_USER_INPUT` / `NEEDS_DECISION` 等状态；重要在于避免 LLM 盲目试错。
