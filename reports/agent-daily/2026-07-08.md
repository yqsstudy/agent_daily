- **时间**：2026-07-07T08:54:00Z

- **一句话摘要**：Google 为 Gemini API Managed Agents 新增后台执行、远程 MCP 服务器集成、自定义函数调用与凭证刷新，帮助开发者构建可靠生产级 AI Agent。
- **文章做了什么**：扩展 Gemini API 托管 Agent 能力：通过 `background: true` 异步运行任务并返回 ID，支持轮询或流式获取进度；直接连接远程 MCP Server；混合使用内置沙箱工具和自定义函数；刷新凭证时保留沙箱文件系统、包和仓库状态。

### Antidoom / FTPO：修复推理模型 doom loop

- **一句话摘要**：Liquid AI 开源 Antidoom，用 Final Token Preference Optimization 定位循环开始 token，训练模型选择连贯替代项，显著降低推理模型死循环率。

- **为什么重要**：虽然是模型层修复，但对 Agent Loop 设计有直接启发：循环必须有检测、退出、修复和防重入机制。

## 新概念/新框架/新协议/新评测

- **Gemini API Managed Agents**：平台托管 Agent Runtime，重要性在于把后台执行、远程 MCP、沙箱、自定义函数、凭证刷新和状态查询集成到生产 API。
- **background: true**：后台执行参数，重要性在于让 Agent 任务从同步请求响应变成异步生命周期管理。
- **Remote MCP Server Integration**：远程 MCP 集成，重要性在于 MCP 进入云端托管 Agent Runtime，工具认证、权限和 trace 更关键。
- **Credential Refresh for Agent Environment**：Agent 环境凭证刷新，重要性在于长任务可更新凭证而保留沙箱文件系统、包和仓库状态。
- **Claude Cowork**：后台知识工作 Agent，重要性在于展示跨文件、邮件、日历、IM 的任务执行、移动端接管和定时任务。
- **Mobile Agent Control Plane**：移动端 Agent 控制面，重要性在于手机成为后台 Agent 的进度查看、决策审批和任务恢复入口。
- **Rowboat Local-first Agent**：本地优先个人 Agent Runtime，重要性在于用 Markdown graph、MCP、背景代理和本地模型组织个人知识工作。
- **DialAgent HITL**：通过电话、短信、iMessage 接入人类决策，重要性在于把 HITL 从网页输入扩展为多通道决策升级。
- **Effort Level**：Agent 执行预算控制，重要性在于控制读文件、验证、测试和推进深度，区别于模型能力本身。
- **Antidoom / FTPO**：推理模型死循环修复方法，重要性在于从模型层减少 doom loop，也启发 Agent Loop 的循环检测和退出机制。
- **Data Systems for, of, and by Agents**：面向 Agent 的数据系统设计方向，重要性在于推理成本下降后，数据系统需要支持 Agent 推测式探索、状态、记忆和工具调用。
