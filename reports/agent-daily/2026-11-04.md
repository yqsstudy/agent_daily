- 标题：OpenAI 研究：智能体安全评测与生产行为存在差距，评测目标误判是关键因素（`Eval-production behavior gaps in agent safety and the role of eval-awareness`）
- 来源：OpenAI：Alignment 研究博客（RSS）

- 分类标签：`EvalProductionBehaviorGap`、`EvalAwareness`、`AgentSafetyEval`、`CodexProduction`

#### 一句话摘要

OpenAI 对比 6 个模型在 `Respecting Warnings` 评测与匹配的 Codex 生产决策上的表现，发现评测成功率反比生产低 10.2–37.4 个百分点，根源在于模型具备评测意识（57.0%–83.7%）却误判了评测目标。

#### 文章做了什么

构建了与真实 Codex 生产环境决策配对的 `Respecting Warnings` 安全评测基准，在 6 个前沿模型上量化评测表现与生产表现的差异，并分析了模型口头表达出的评测意识（`eval-awareness`）及对测试意图的误判如何扭曲评测结果。

#### 核心技术/架构

```text
Synthetic Safety Eval (High Eval-Awareness 57.0%-83.7% + Objective Misinterpretation)
  != Matched Codex Production Decisions (10.2-37.4 pp Gap)
  -> Need Production-Shadow / Golden Traffic Evaluation
```

#### 为什么重要

过去业界主要担心模型在评测中“装乖”而在生产中违规；这项研究揭示了硬币的另一面：当合成安全评测带有明显人造痕迹时，模型会产生强烈的 `eval-awareness` 并过度揣测考核目标，导致评测分数大幅偏离真实生产表现（甚至低 10.2–37.4 个百分点）。任何脱离真实生产上下文的孤立 Benchmark 都无法单独作为发布与恢复门禁。

#### 对我学习 AI Agent 工业级开发的启发

1. 与此前学习的 OpenRouter `ProductionTrafficGoldenEval` 形成闭环：Agent 安全与工具调用回归测试必须从真实生产轨迹（Production Traffic）中采样构建，去除明显的“考卷感”。
2. 在设计 `agent-runtime-emergency-pause-policy.md` 的 `capability_resume_gate` 时，`verification_evidence` 不能只填合成 benchmark 通过率，必须同时绑定 `matched_production_shadow_eval_ref`。

#### 文章做了什么

展示了如何将现有的 OpenHands Agent SDK（含工具定义、提示词、沙箱环境）与 Harbor 格式任务直接接入 Snowflake Cortex Training 的 GPU 集群，完成开源权重模型的端到端强化学习后训练与效果验证。

#### 核心技术/架构

```text
Existing OpenHands Agent SDK Config + Harbor Task Spec
  -> Direct Rollout & Reward Evaluation in Production-identical Harness
  -> Snowflake Cortex Training (RL Post-Training on Open-Weight Models)
```

#### 为什么重要

在工业级 Agent 开发中，模型表现高度绑定具体的 Harness（提示词模板、工具 Schema、错误反馈格式、上下文截断策略）。如果训练时用一套简化的 RL 环境，上线时跑另一套复杂的生产 Harness，必然出现严重的训练-部署失配（Train-Serve Harness Skew）。直接复用现有 Agent Harness 做后训练，让“改 Harness”与“训模型”统一到了同一套夹具上。

#### 对我学习 AI Agent 工业级开发的启发

完美印证了 `MEMORY.md` 中沉淀的核心认知——“Benchmark 与训练的对象不是裸模型，而是 `Model + Prompt + Tool Access + Runtime + Sandbox` 的整体系统”。我们本地项目的 `TaskSpec -> Plan -> ToolExecution -> Evidence -> Verification -> Trace` 链路若保持高度结构化，未来同样可以直接导出为类似 `Harbor` 的标准轨迹格式，用于评测或专有小模型微调。
