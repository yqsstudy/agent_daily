### 2. Mistral Agentic Search：RAG 进入多步可验证检索循环

- 标题：Mistral 推出 Agentic Search：多步检索提升 AI 系统复杂文档查询准确率
- 来源：Mistral AI News
- 时间：2026-08-20T16:02:07Z
- 链接：https://mistral.ai/news/agentic-search
- 分类标签：`Agentic RAG`、`agentic search`、`tool loop`、`source trace`、`evidence verification`、`grep`
- 一句话摘要：Mistral 发布 Agentic Search，通过 `search / open / navigate / read / grep` 五工具的多步检索循环，让模型在长文档与多来源中查找、定位并验证信息。

文章做了什么：

- 发布多步检索层，面向复杂文档查询。
- 让模型通过工具循环查找、打开、导航、阅读与 grep。
- 强调比单次检索更适合长文档和多来源验证。

核心技术/架构：

```text
query
-> search
-> open
-> navigate
-> read
-> grep
-> verify
-> answer_with_evidence
```

为什么重要：

- 这是 Agentic RAG 的标准工程形态：不是一次向量召回，而是多步搜索、定位、读取和验证。
- 每一步都可以生成 `EvidenceRef`，使最终回答更接近 `No Source, No Claim`。
- 适合映射到本地 `RAG_EVIDENCE / AGENT_CONCLUSION / Source Trace`。

对我学习 AI Agent 工业级开发的启发：

- `RAG_EVIDENCE` 应支持 `search_results / opened_sources / navigation_steps / read_passages / grep_matches / verification_status`。
- `AGENT_CONCLUSION` 必须引用已读、已验证的 evidence，而不是仅引用搜索结果标题。

## 新概念/新框架/新协议/新评测

- **Production Agent Platform**：把 Computer Use、Skills、Files、Browser Tool 打包成平台能力；重要性在于 Agent 能力栈开始工程平台化。
- **Computer Use / Browser Tool**：Agent 直接操作软件和浏览器；重要性在于外部副作用必须由权限、sandbox、证据截图和回滚治理。
- **Skills API**：通过 API 调用团队技能；重要性在于 Skill 变成可版本化、可权限化、可审计的能力单元。
- **Files API / FileArtifact**：Agent 输入、处理、返回文件；重要性在于交付物需要来源、权限、保留策略和 trace。
- **Agentic Search**：多步检索、打开、导航、阅读、grep 的循环；重要性在于 RAG 变成可验证过程。
- **GUI Agent Foundation Model**：面向 GUI 操作的 Agent 基座模型；重要性在于界面操作能力进入模型层。
- **AlloyDB ScaNN Four-level Tree**：百亿向量规模检索索引；重要性在于 Agentic RAG 的底层检索规模、延迟和召回能力提升。
- **LFM2.5-DSpark**：投机解码草稿模型；重要性在于函数调用延迟下降会改善 Agent tool loop 体验。
- **4D AI Fluency Framework**：AI 学习能力框架；重要性在于学习型 Agent 要培养问题框架，而不是只教操作步骤。
- **Trust but Verify for Agentic Coding**：信任但验证；重要性在于 Coding Agent 交付必须经过测试、review 和风险检查。
