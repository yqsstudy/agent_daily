## 今日重点讨论补充

### Agent Memory 类型边界

今天讨论了 Agent 的记忆类型，重点结论：

```text
Memory != State
Memory != Evidence
Memory != Trace
Memory != Knowledge Base
```

建议分层：

```text
Session Memory       当前对话上下文
Working Memory       当前推理和执行草稿
State Memory         任务状态、pending、resume、revision
User Memory          用户偏好、长期目标、项目路径
Semantic Memory      文档、知识库、RAG、学习笔记
Episodic Memory      具体事件、日报、commit、失败案例
Procedural Memory    skill、workflow、checklist、recipe
Reflection Memory    晚总结、周复盘、memory dreaming
```

对本地项目的映射：

```text
PendingInput / suspended_metadata -> State Memory
AGENT_CONCLUSION citations        -> Evidence
Tool call logs                    -> Trace
agent-learning notes              -> Semantic / Procedural Memory
晚总结 / 周复盘                   -> Reflection Memory
```

## 新概念/新框架/新协议/新评测

- **Over-agentic Behavior**：模型为了完成任务采取超出用户意图的动作；重要性在于强 Agent 更需要外部权限系统约束。
- **Destructive Action Guardrail**：对删除、覆盖、终止、部署、读取凭据等高风险动作进行检测、分级、确认、备份和回滚；重要性在于防止 Agentic Coding 造成真实破坏。
- **Repository Trust Check 2.0**：打开仓库前检查 workspace binary、PATH hijack、IDE auto-exec surface，并使用隔离环境；重要性在于 AI IDE 的仓库打开动作本身可能触发执行。
- **Agent Output Middleware / Hook**：在模型输出显示前进行过滤、替换、审计或格式化；重要性在于 Agent Runtime 需要可插拔输出控制层。
- **Skill Hub as Workflow Registry**：Skill 不只是 prompt，而是可编辑节点工作流；重要性在于 Skill 工业化要支持节点、资产、自查和返修。
- **端侧 Computer Use Agent**：在手机或设备端运行具备工具调用、视觉和计算机使用循环的模型；重要性在于本地 Agent 将具备真实执行能力，必须有端侧权限和 trace。
- **Usage Analytics for Agent Products**：统计任务分布、地区、场景和使用比例；重要性在于 Agent 产品需要 telemetry 支撑迭代和治理。
- **Agent Memory Taxonomy**：将 Agent 记忆分为 session、working、state、user、semantic、episodic、procedural、reflection；重要性在于避免把状态、证据、知识和偏好混在一起。
- **Destructive Action Eval**：评测 Agent 是否会执行删除、强制移除、kill、凭据滥用等动作；重要性在于覆盖真实高风险工具执行。
- **Repository Open Safety Test**：测试打开不受信任仓库是否会触发自动执行；重要性在于 AI IDE 必须把 open repo 视为潜在执行动作。
