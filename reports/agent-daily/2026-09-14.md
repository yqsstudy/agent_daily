- **标题**：Agent 长任务上下文工程解析：用预算控制、压缩、todo-state 和记忆对抗上下文溢出与目标丢失
- **来源**：MarkTechPost（RSS）
- **时间**：2026-09-13T05:56:03Z
- **链接**：https://www.marktechpost.com/2026/09/12/context-engineering-inside-the-harness-4-mechanisms-that-beat-context-overflow-and-goal-loss-on-long-horizon-tasks
- **AIHOT permalink**：https://aihot.news/items/cmtzezuk0077wrowyi7a4qy7v
- **分类标签**：`context engineering`、`agent harness`、`long-horizon task`、`memory`、`runtime governance`

#### 一句话摘要

文章总结长任务 Agent 在 harness 层对抗上下文溢出和目标丢失的四类机制：上下文预算与卸载、压缩、todo-state 复述和跨会话记忆。

#### 文章做了什么

文章把长任务 Agent 的上下文稳定性问题从 prompt 层提升到 harness/runtime 层，讨论如何在长任务中持续保留目标、证据、决策历史和下一步行动。

#### 核心技术/架构

- `context budget`：为长任务设置上下文预算与阈值；
- `offloading`：把不必常驻上下文的信息卸载到外部存储；
- `compression`：压缩历史交互、代码阅读、证据和决策；
- `todo-state restatement`：定期重述目标、待办和阻塞；
- `cross-session memory`：跨会话恢复任务状态；
- `resume policy`：恢复任务时检查目标和上下文是否一致。

#### 为什么重要

工业级 Agent 的失败经常不是模型完全不会，而是长任务执行中出现：

- 上下文溢出；
- 目标漂移；
- 压缩丢证据；
- resume 后状态不一致；
- memory 陈旧或污染。

这篇文章适合直接转化为 `LongHorizonAgentContextPolicy`，并映射到 coding agent runtime。

## 新概念 / 新框架 / 新协议 / 新评测

### 1. LongHorizonAgentContextPolicy

定义长任务 Agent 如何管理上下文预算、压缩、卸载、todo-state、跨会话记忆和恢复点。重要性：长任务 Agent 的稳定性需要 harness/runtime 管理，而不是只靠 prompt。

### 2. ContextOverflowGuard

当上下文接近阈值时触发 offload、compression 或 checkpoint。重要性：避免上下文溢出导致目标丢失和证据丢失。

### 3. Todo-State as Working Memory

把 todo 状态作为 Agent 的显式工作记忆。重要性：长任务中必须持续重述目标、下一步、阻塞和已完成事项。

### 4. DualUseCodingAgentBoundary

定义 coding agent 在武器、恶意软件、诈骗、无人机等高风险领域的能力边界。重要性：高能力 coding agent 需要用途识别、拒绝、降级和人工审查机制。

### 5. EvaluatorIndependenceContract

定义第三方评估者的资金来源、利益冲突、公开报告和监管接口。重要性：第三方 access 不等于真正独立。

### 6. RuntimeAbuseMonitoringSchema

记录 Agent 发布后的滥用信号、风险域、工具链和处置动作。重要性：release gate 只能覆盖发布前风险，真实滥用发生在运行时。
