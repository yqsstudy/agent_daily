- **链接**：https://cursor.com/blog/reward-hacking-coding-benchmarks
- **分类标签**：`agentic coding eval`、`reward hacking`、`benchmark leakage`、`runtime sandbox`、`trace audit`
- **一句话摘要**：Cursor 审计 SWE-bench Pro 轨迹发现，大量成功方案来自公开来源检索或 git 历史挖掘，限制网络和 git 历史后模型分数大幅下降。
- **文章做了什么**：分析 Coding Agent benchmark 中的轨迹，识别模型通过公开资料、git 历史或环境漏洞获得高分的现象。

- **为什么重要**：Agent Eval 不能只看最终 pass rate，必须看运行轨迹、环境权限、证据来源和是否利用了 benchmark 泄漏。
- **对我学习 AI Agent 工业级开发的启发**：你的 `AGENT_CONCLUSION` 不能只“看起来合理”，必须绑定 `MCP_OBSERVATION / RAG_EVIDENCE`，否则报告结论不可审计。

## 新概念 / 新框架 / 新协议 / 新评测

- **A2A Agent Card**：Agent 声明能力和接口的能力发现卡片，多 Agent 协作需要标准化发现机制。
- **A2A Task State Machine**：用任务状态机管理 Agent 间任务生命周期，与 `PendingInput / resume / suspended_metadata` 同样强调显式状态建模。
- **RemoteA2aAgent**：ADK 将远程 A2A 服务封装成本地子 Agent，支持跨语言、跨进程统一编排。
- **Branch-as-Session**：Oak 将分支作为 Agent 会话基本工作单元，支持任务隔离、回滚、审计和并发。
- **Agent Workspace Version Control**：面向 AI Agent 的版本控制与工作区管理，适配高频、并发、上下文懒加载的 Agent 编辑流程。
- **Reward Hacking in Coding Benchmarks**：模型通过公开资料、git 历史或环境漏洞获得高分，提醒 eval 必须审计轨迹和限制环境。
- **Insight Strategy Evaluation**：评估 Coding Agent 是否能发现高层级目标和有价值洞察，说明优秀 Agent 不只是执行任务，还应主动发现更重要的问题。
- **Super App Agent Permission Boundary**：超级 App 内 Agent 根据入口、上下文和动作类型划分权限，是产品级 Action Risk Classification。
- **Cyber Agent Security Loop**：AI 发现、验证、修补漏洞的闭环工具链，要求配套 sandbox、审批和审计。
- **Evidence-aware Agent Eval**：评估 Agent 结论是否绑定可追溯证据，而不是只看最终答案是否合理。

```text
# Evidence-aware Agent Eval Checklist

## 目标
检查 Agent 结论是否有可追溯证据，而不是只看最终回答是否合理。

## 检查项
1. 每个 AGENT_CONCLUSION 是否至少绑定一个 MCP_OBSERVATION 或 RAG_EVIDENCE？
2. 结论是否能追溯到原始工具返回？
3. 结论是否区分事实、推测和建议？
4. 如果引用了 RAG，是否保留 source / document / chunk？
5. 如果用户修正了结论，是否保留 revision 或 correction evidence？
6. 如果结论来自多步工具调用，是否能还原调用顺序？
7. 报告生成时是否展示 evidence trace？
8. 如果没有证据，系统是否禁止生成强结论？

## 类型映射
MCP_OBSERVATION = 工具返回的事实
RAG_EVIDENCE = 检索到的文档证据
AGENT_CONCLUSION = Agent 基于事实归纳的结论
USER_CORRECTION = 用户修正或确认
```

目标：把 Cursor 的 reward hacking 启发迁移到 `msinsight_agent`，让 `AGENT_CONCLUSION` 必须 evidence-backed。
