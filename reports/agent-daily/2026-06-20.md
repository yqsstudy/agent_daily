### Deep Agents 三层架构：Runtime / Framework / Harness

- **来源**：X：邵猛
- **时间**：2026-06-20T12:16:16Z
- **链接**：https://x.com/shao__meng/status/2068306942184034471
- **分类标签**：`agent architecture`、`runtime`、`framework`、`harness`、`LangGraph`、`LangChain`
- **一句话摘要**：Deep Agents 实战教程将真实 Agent 应用拆成 Runtime、Framework、Harness 三层。
- **文章做了什么**：用 LangGraph 表示 Runtime，用 LangChain 表示 Framework，用 Deep Agents 表示 Harness，说明构建真实 Agent 应用不能只停留在模型调用或工具调用。
- **核心技术/架构**：Runtime 负责状态图和执行，Framework 负责模型/工具/链路封装，Harness 负责组织任务、上下文、子 Agent 和 Skills。
- **为什么重要**：三层拆分能避免把所有 Agent 能力混在一起，有利于定位系统边界、扩展点和测试点。
- **对我学习 AI Agent 工业级开发的启发**：你的 `Orchestrator / PendingInput / Evidence / SessionStore / ReportGenerator` 可以统一看成自研 Harness 的组成部分，而不是零散工具代码。
- **后续追踪问题**：你的系统中哪些模块承担 Runtime 角色，哪些承担 Framework 角色，哪些承担 Harness 角色？

## 新概念 / 新框架 / 新协议 / 新评测

- **Deep Agents Harness**：把模型、工具、上下文、计划、子任务和 Skills 包装成真实 Agent 应用的控制层，贴近生产级 Agent 的工程核心。
- **Runtime / Framework / Harness 三层架构**：Runtime 负责执行状态图，Framework 负责模型和工具封装，Harness 负责应用级任务控制和上下文组织。
- **Virtual File System for Context Engineering**：通过虚拟文件系统按需读取、局部读取大文件、保存中间结果，解决上下文窗口和中间态管理问题。
- **Sub-agent Delegation**：主 Agent 将子任务委派给子 Agent 异步并行执行，重点是任务分派、隔离、合并和失败处理。
- **Reusable Skills**：把稳定任务流程封装成可跨工具复用的 Skill，让 prompt 技巧升级为工程资产。
- **Model Marketplace / Model Middleman**：云厂商统一采购、转售和路由多个模型，是企业 Agent 模型访问层的重要趋势。
