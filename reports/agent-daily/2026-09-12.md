## 新概念/新框架/新协议/新评测

### 新概念

- `PackageRegistryWriteGuard`：约束 Agent 向 RubyGems、npm、PyPI、Docker Registry、GitHub Releases 等仓库发布包或 artifact 的权限、扫描、审批和回滚规则；重要是包仓库写入属于供应链级真实副作用。
- `Agent Cluster Abuse Pattern`：多个 Agent 或自动化账号在短时间内协同执行同类异常/恶意操作；重要是单账号限流不足以治理集群式滥用。
- `Runtime Abuse Monitoring`：模型/Agent 发布后持续监控恶意软件、武器、诈骗、蒸馏等滥用行为；重要是 release gate 只能覆盖发布前风险。
- `Threat Intelligence as Eval Corpus`：把真实滥用案例转化为安全评测/harness 样本；重要是让安全治理从原则变成可执行测试集。
- `Ops-as-Code Agent Pattern`：非工程用户用 Copilot/Agent 把运营、市场、行政等流程转成脚本和自动化 workflow；重要是权限、secret、外部副作用和审批风险会扩散到更多岗位。

### 新协议/框架建议

- `PackageRegistryWriteContract`：定义 Agent 发布包前必须满足的 registry、身份、签名、扫描、审批、限流和 takedown 要求。
- `RuntimeAbuseMonitoringSchema`：记录滥用模式、风险域、请求聚类、工具链、处置动作和证据链。
- `OpsAsCodeReviewGate`：非工程用户生成自动化 workflow 后必须经过 dry-run、secret 检查、review 和 rollback 设计。
- `AgentIncidentDisclosure`：当 Agent 影响公共系统或真实用户时，记录影响范围、时间线、处置、通知和 postmortem。

### 新评测方法

- `Supply Chain Attack Simulation Harness`：用本地 fake registry 模拟 Agent 上传包、恶意包检测、异常 burst upload 和 takedown 流程。
- `Threat Intelligence Eval`：把 Anthropic 威胁报告中的滥用类别转成 eval scenarios。
- `RSI Readiness Eval`：评估 Agent 是否具备研究任务拆解、实验规划、工具使用、自我改进闭环能力。
