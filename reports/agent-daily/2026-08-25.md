- 标题：OpenAI 正为一切构建 AI 智能体，但用户会愿意交出控制权吗？
- 来源：TechCrunch：AI（RSS）
- 时间：2026-08-24T15:00:00Z
- 链接：https://techcrunch.com/2026/08/24/openai-is-building-an-ai-agent-for-everything-will-everyone-use-them
- 分类标签：`ChatGPT Work`、`general-purpose work agent`、`Codex`、`control handoff`、`human-in-the-loop`、`workflow automation`
- 一句话摘要：OpenAI 推出 ChatGPT Work，将 Codex 改造为面向非工程师的智能体产品，最低订阅档每月 20 美元即可使用，试图让白领通过 LLM 自主完成多步骤工作。

文章做了什么：

- 报道 OpenAI 将 Codex 能力扩展到非工程师工作场景。
- 指出 OpenAI 内部 6 月有 98% 员工使用 Codex，但组织订阅者仅 17%、个人订阅者不足 1%。
- 将 Agent 产品化难点聚焦到“用户是否愿意交出控制权”。

核心技术/架构：

```text
user_intent
-> task_boundary
-> control_handoff
-> multi-step work agent
-> progress_trace
-> permission_gate
-> user_override / rollback
-> final_approval
```

为什么重要：

- Agent 工业落地不只是自动完成任务，还要让用户保留控制感、可见性和回滚权。
- 面向非工程师的 Agent 更需要清晰的权限边界和 human-in-the-loop，否则 adoption 会被信任问题限制。

对我学习 AI Agent 工业级开发的启发：

- 应把 `Control Handoff` 建模为独立 schema，而不是普通授权弹窗。
- 可映射到你一直关注的 `PendingInput / PermissionDecision / TraceEvent / EvidenceRef / RecoveryFeedback`。

## 新概念/新框架/新协议/新评测

- **ChatGPT Work**：面向白领的通用工作 Agent；重要性在于 Agent 从开发者场景扩展到普通办公任务。
- **Control Handoff**：用户将多步骤任务控制权交给 Agent 的过程；重要性在于 adoption、权限确认、进度可见和回滚都依赖它。
- **Work Agent Permission Scope**：工作 Agent 可做/不可做动作的边界；重要性在于防止 Agent 自动发送邮件、删除文件或外部分享。
- **Cost per Solved Task**：每个成功任务的成本；重要性在于比 token 单价更接近 Coding Agent 的真实 ROI。
- **Terminal-Bench 2.1**：面向终端任务的 Coding Agent benchmark；重要性在于比代码补全更接近真实工程任务。
- **Agent Workload Efficiency**：以 Agent 多步任务为单位衡量硬件/serving 效率；重要性在于多步 Agent 对尾延迟、成本和恢复更敏感。
- **MetaRoCE**：Meta 开源的 AI-scale Ethernet RDMA 传输协议；重要性在于支撑大规模 AI/Agent serving 的低尾延迟和高吞吐。
- **Tail Latency Governance**：对 p95/p99 尾延迟进行治理；重要性在于多步 Agent 会把单次慢调用放大成整体体验失败。
